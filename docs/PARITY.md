# Daily Puzzle parity with iOS

The Daily Puzzle deals the same board on the web and in the iOS app. That works because both apps
generate the board from the same seed with exactly the same arithmetic.

## How the board is made

1. **Seed from the date.** Take the local calendar date as `yyyymmdd` (e.g. `20260929`), XOR it with
   `0x1A5A2E000C0FFEE5`, and take one output of SplitMix64 seeded with that value.
2. **Generator.** SplitMix64 (64-bit state, the standard constants).
3. **Tile draws.** Each tile kind is `Int.random(in: 1...5, using: &rng)` in Swift. Swift implements
   this with Lemire's multiply-shift method with rejection (`next(upperBound:)` on unsigned 64-bit
   values). `src/model/rng.ts` reproduces that algorithm bit for bit using `BigInt`.
4. **Draw order.** One draw for the "next tile" value, then row by row, top to bottom, left to right.

Change any of these on one platform and the Daily boards diverge.

## The fixtures

Both test suites check the same three things:

| Check | Expected |
|---|---|
| SplitMix64 seeded with 0, first three outputs | `0xE220A8397B1DCDAF`, `0x6E789E6AA1B965F4`, `0x06C45D188009454F` (the published reference sequence) |
| Puzzle board for seed 42 | 8 rows, starting `122152524233` |
| Daily #272 (29 Sep 2026) | seed `0x8A7BAE707C98FCFE`, rows starting `455524513525` |

- Web: `tests/parity.test.ts` (runs in `npm test` and in CI).
- iOS: `InsaneGameTests/PlatformParityTests.swift` (run with ⌘U in Xcode).

The expected boards were generated by the TypeScript port. **If the iOS parity tests pass on your Mac,
the two apps are confirmed to deal identical boards.** If they fail, the Swift test output shows the
first row that differs.
