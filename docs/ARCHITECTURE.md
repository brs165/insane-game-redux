# Architecture

TypeScript + Vite, no UI framework. The game model is plain TypeScript with no DOM access, so it
runs in Node for tests; the renderer draws on a `<canvas>`; the screens are small DOM modules.

```
src/
  main.ts            Boot: fonts, styles, App, PWA registration
  app.ts             App (≈ AppModel.swift): stores, navigation, sheets, toasts, global keys
  session.ts         GameSession (≈ GameSession.swift): scene events → sound, vibration, achievements, result
  pwa.ts             Service worker registration, update banner, install prompt / iOS hint
  model/             Pure game logic, fully unit-tested
    rng.ts           SplitMix64 + exact ports of Swift's bounded random functions
    board.ts         12 × 8 grid, flood fill, gravity, Action spawn order
    engine.ts        Rules, scoring, Action timing, modes
    daily.ts         Daily seed, puzzle number, day keys
    progress.ts      Per-mode stats, Daily history, streaks, achievements
    scores.ts        Top five with initials (Puzzle, Action)
    settings.ts      Preferences
    store.ts         localStorage wrapper (memory fallback) + change emitter
  game/
    scene.ts         Canvas renderer (≈ GameScene.swift): animation, particles, input
    tileArt.ts       All art drawn in code: gem tiles, LCD bitmaps, well, title bitmap
  audio/
    sound.ts         Web Audio synthesizer (≈ SoundEngine.swift)
    haptics.ts       Vibration API (Android only)
  ui/
    menu.ts          Title screen with the self-playing demo board
    game.ts          HUD, pause, game over, initials, share
    sheets.ts        How to Play (with animated mini board), Statistics, Settings
    dom.ts, icons.ts Helpers, shared HTML fragments, inline SVG icons
  styles.css         All styling; one dark theme, mode accent via [data-mode]
tests/               Vitest: rules, progress, iOS parity fixtures
public/icons/        PWA and Apple touch icons (generated by scripts/make_icons.py)
```

## iOS → web mapping

| iOS (Swift) | Web (TypeScript) |
|---|---|
| `Board`, `GameEngine`, `DailyPuzzle` | `model/board.ts`, `model/engine.ts`, `model/daily.ts` (line-for-line) |
| `ProgressStore`, `ScoreStore`, `Settings` (UserDefaults) | `model/progress.ts`, `model/scores.ts`, `model/settings.ts` (localStorage) |
| SpriteKit `GameScene` | `game/scene.ts` on Canvas 2D |
| `TileArt` (Core Graphics) | `game/tileArt.ts` (Canvas 2D) |
| `SoundEngine` (AVAudioEngine) | `audio/sound.ts` (Web Audio) |
| `Haptics` (Taptic Engine) | `audio/haptics.ts` (Vibration API, Android only) |
| SwiftUI views | `ui/*.ts` + `styles.css` |
| Share sheet | Web Share API, clipboard fallback |
| Game Center | Not available; scores stay on the device |

## Data flow

```
pointer/keys ─▶ GameScene ─▶ GameEngine (rules) ─▶ GameScene animates
                     │
                     └─ SceneDelegate events ─▶ GameSession ─▶ sound, vibration, ProgressStore
                                                        └─▶ GameScreen (HUD, overlays)
```

The engine is authoritative and changes instantly; the scene's per-tile animation state chases each
tile's real cell every frame (fall with gravity first, then slide left), like the SpriteKit version.

## Storage

All data stays in the browser's `localStorage`:

| Key | Contents |
|---|---|
| `insane.settings.v1` | Sound, vibration, classic screen, tap style, last mode, last initials, tutorial seen |
| `insane.scores.v1` | Top five per mode |
| `insane.progress.v1` | Per-mode stats, Daily best per day, achievement unlock dates |
| `insane.installHintDismissed` | Whether the iPhone install hint was closed |

On the first tap the app asks for persistent storage (`navigator.storage.persist()`), which makes
eviction less likely. Installing to the Home Screen gives the best protection on iPhone.

## PWA

- `vite-plugin-pwa` (Workbox `generateSW`) precaches every built file: HTML, JS, CSS, fonts, icons.
  After the first visit the game runs fully offline.
- `registerType: 'prompt'`: a new deployment triggers the *"A new version is ready"* banner instead of
  swapping code mid-game.
- The manifest uses relative `start_url`/`scope`, so the same build works at any GitHub Pages path.
- Fonts are bundled from `@fontsource` packages, not loaded from Google, so they work offline.
